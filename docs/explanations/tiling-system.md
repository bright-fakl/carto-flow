# Tiling System

## Overview

The tiling system generates regular grids of congruent polygons that cover a geographic bounding box. Its primary role is to provide tile positions for the [grid-based layout algorithm](symbol-cartogram-grid-layout.md) and the [mosaic layout algorithm](symbol-cartogram-mosaic-layout.md): each tile becomes a candidate slot for one symbol. Tiles are generated by a `Tiling` subclass, and the result is a `TilingResult` containing tile geometries, per-tile transforms, and adjacency information.

The tilings are [isotile](https://bright-fakl.github.io/isotile/) tilings. isotile generates the tiles, their curved edges and their adjacency; this module adds the size conventions (`tile_size`), the symbols that fit the tiles, and the `TilingResult` format that the layouts use.

Source: [tiling.py](https://github.com/bright-fakl/carto-flow/blob/main/src/carto_flow/symbol_cartogram/tiling.py)

## Tiling Types

Five concrete tiling classes are provided, covering all regular and semi-regular polygon tilings used in cartography:

| Class | `tile_size` is | Description |
|-------|----------------|-------------|
| `SquareTiling` | the side | Regular axis-aligned squares |
| `HexagonTiling` | the circumradius | Regular hexagons; `pointy_top` selects pointy-top (default) or flat-top tiles |
| `TriangleTiling` | the square root of the tile area | Any triangle; convenience constructors for equilateral, right isosceles, isosceles |
| `QuadrilateralTiling` | the square root of the tile area | Any simple quadrilateral, convex or not; convenience constructors for parallelogram, rectangle, rhombus, trapezoid |
| `IsohedralTiling` | the square root of the tile area | 81 Grünbaum–Shephard isohedral types with numeric parameters and customizable edge curves |

All classes share the same `generate(bounds, n_tiles=None, tile_size=None, margin=0.1, adjacency_type="edge", compute_adjacency=True)` interface. Either the number of tiles or the tile size must be specified.

### Which tiles are returned

`generate` expands `bounds` by `margin` (a fraction of the width and of the height on each side) and returns every tile that overlaps the expanded region with positive area. A tile that only touches the region is not returned. With `n_tiles`, the tile area is the area of the expanded region divided by `n_tiles`; the tiles along the boundary come on top of that count.

The lattice is anchored at the center of the expanded region and does not depend on the distance of the region from the origin. A region that is expanded by the same amount on all four sides therefore keeps its tiles: every tile of the region is a tile of the expanded region. The mosaic layout relies on this when it builds a trial tiling and a final tiling on larger bounds.

For tilings with curved edges the tiles are selected by their straight-edge outline, so a curve that bulges across the boundary of the region does not add a tile.

The order of the tiles in `TilingResult` is not part of the interface, and neither is the start vertex of a tile polygon.

## TilingResult

`generate()` returns a `TilingResult` dataclass:

| Field | Type | Description |
|-------|------|-------------|
| `polygons` | list of `Polygon` | Tile geometries in world coordinates |
| `transforms` | list of `TileTransform` | Per-tile center (area centroid of the polygon), rotation (degrees) and `flipped` flag, relative to `canonical_tile` |
| `adjacency` | `scipy.sparse.csr_array` | Boolean sparse adjacency matrix of the kind given by `adjacency_type` |
| `vertex_adjacency` | `scipy.sparse.csr_array` or None | Boolean sparse vertex-only adjacency matrix (tiles that share a vertex and no edge); `None` for a loaded result |
| `tile_size` | float | Tile size used for generation |
| `inscribed_radius` | float | Distance from the center of the canonical tile to its boundary |
| `canonical_tile` | `Polygon` | Tile shape before applying transforms, centered at its centroid, at the generated size |
| `n_base_vertices` | int or None | Number of vertices of the prototile of an isohedral tiling |
| `tile_set` | `isotile.TileSet` or None | The isotile tiles in the order of `polygons`, with the cell and aspect of each tile; `None` after `rotate` or when a result is loaded from a file |

`adjacency_type` is `"edge"` (tiles that share an edge), `"vertex"` (tiles that share an edge or a vertex) or `"vertex-only"`. `vertex_adjacency` is always the vertex-only matrix. Adjacency comes from the lattice table of the tiling type, so it is exact for every tile shape, curved ones included. The matrices are symmetric and the column indices of every row are sorted, so the neighbors of tile `t` are `adjacency.indices[adjacency.indptr[t]:adjacency.indptr[t + 1]]`. The memory of a matrix grows with the number of tiles, not with its square. With `compute_adjacency=False` both matrices have the right shape and no stored entries. `SymbolCartogram.save` does not write the adjacency; a loaded result has an empty `adjacency` and `vertex_adjacency=None`, which is enough for plotting.

A tile with `flipped=True` is the canonical tile mirrored about the vertical axis, then rotated by `rotation` degrees, then moved to `center`.

## Isohedral Tilings

### Mathematical Definition

A tiling is **isohedral** (IH) if every tile is congruent and the symmetry group of the tiling acts transitively on its tiles: for any two tiles $T$ and $T'$, there exists a symmetry transformation of the entire tiling that maps $T$ to $T'$. All 81 isohedral types in the plane are classified in Grünbaum and Shephard's *Tilings and Patterns* (1987).

`IsohedralTiling` is an [`isotile.IsohedralTiling`](https://bright-fakl.github.io/isotile/) used as a `Tiling`, available as `tiling.isotile`. Each type is identified by its IH number (1–93, with gaps) and zero or more real-valued shape parameters. The type data derive from the tiling data of [tactile](https://github.com/isohedral/tactile) by Craig S. Kaplan.

### Edge Shape Types

Each tile edge in an isohedral tiling is assigned a shape constraint by the tiling's symmetry group:

| Type | Symbol | Constraint |
|------|--------|-----------|
| Straight | I | Edge is a straight line segment; not customizable |
| Free | J | Edge curve is fully customizable |
| Rotationally symmetric | S | The curve at parameter $t$ equals the curve at $1-t$ rotated 180° about the edge midpoint |
| Mirror symmetric | U | The curve is symmetric about the perpendicular bisector of the edge |

When an edge curve is provided, it is defined in canonical edge space as a polyline from $(0, 0)$ to $(1, 0)$, where perpendicular displacement encodes the curve shape. The symmetry constraint of S and U edges is enforced on the control points by position along the curve: the first half is kept and the second half is derived from it, so a curve that already has the symmetry is unchanged. A spline through $m$ control points is sampled at $\max(100, 10m)$ points.

A curve is rejected with `ValueError` if the prototile with its curves is not a simple polygon (edges that cross, touch or come within $10^{-6}$ of the prototile diameter of each other), and if it is given for an I edge.

### Querying and Creating

```python
from carto_flow.symbol_cartogram.tiling import IsohedralTiling

# All triangle-based types with customizable edges
types = IsohedralTiling.find_types(num_vertices=3, has_customizable_edges=True)

# Type metadata
info = IsohedralTiling.type_info(10)
# → {'num_parameters': 0, 'num_vertices': 6, 'edge_shapes': ['J','J','J'], ...}

# Create from type number with optional shape parameters
tiling = IsohedralTiling(tiling_type=68, parameters=[0.25])

# Load a preset configuration (parameters + edge curves)
tiling = IsohedralTiling.from_preset("scalloped_hexagon")
```

`available_types`, `find_types`, `type_info`, `describe`, `list_presets`, `from_preset`, `to_dict`, `from_dict`, `save`, `load` and `plot_prototile` call the functions of isotile of the same purpose.

### Edge Curves

```python
# Assign custom edge curves (polyline in canonical edge space)
tiling = IsohedralTiling(
    tiling_type=41,
    edge_curves={
        0: [(0, 0), (0.25, 0.12), (0.5, 0), (0.75, -0.12), (1, 0)],
        1: [(0, 0), (0.25, -0.12), (0.5, 0), (0.75,  0.12), (1, 0)],
    }
)
```

Only edges of type J, S, or U accept curves. `edge_curve_modes` selects `"spline"` (default) or `"linear"` interpolation per shape id.

## Symbol–Tile Correspondence

Each `Tiling` subclass has a `canonical_symbol()` method that returns the `Symbol` instance matching the tile shape. This ensures symbols fit tiles correctly without explicit alignment:

| Tiling | Canonical symbol |
|--------|-----------------|
| `SquareTiling` | `SquareSymbol` |
| `HexagonTiling` | `HexagonSymbol(pointy_top=...)` |
| `TriangleTiling`, `QuadrilateralTiling` | `TileSymbol(canonical_tile)` |
| `IsohedralTiling` | `IsohedralTileSymbol(...)` |

`tiling.tile_size_for_symbol_size(symbol_size, spacing)` computes the tile size required to contain a symbol of a given area-equivalent radius, accounting for the desired spacing gap.

---

Tilings can be saved to JSON with `tiling.save("path.json")` and reloaded with `IsohedralTiling.load("path.json")`. The file holds the type, parameters, edge curves with their modes and the frame of the tiling; the format is described in the isotile documentation.

## Integration with Layouts

When `GridBasedLayout` runs, it calls `tiling.generate(bounds, tile_size=...)` to produce enough tiles to cover the input regions, then passes the `TilingResult` to `assign_to_grid_hungarian()`. Tile adjacency from `TilingResult.adjacency` is used directly in the BFS hop-distance computation of the neighbor cost term. See [Grid Layout Algorithm](symbol-cartogram-grid-layout.md) for details.

`MosaicLayout` calibrates the tile size with trial tilings of the bounds of the study area and builds the final tiling on bounds that are expanded by the same amount on all sides; because the lattice is anchored at the center of the region, the trial tiles are tiles of the final tiling. See [Mosaic Layout Algorithm](symbol-cartogram-mosaic-layout.md).
